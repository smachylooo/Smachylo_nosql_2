# Семантичний пошук статей arXiv

Навчальний проєкт: 5 000–10 000 статей → SPECTER2 → Pinecone → семантичний пошук, фільтри, порівняння метрик і чанкінгу; додатково BM25 + RRF. Скрипти 01–06 виконано на 10 000 статей; результати наведено нижче та у папці `results/`.

## Підготовка

1. Створіть Pinecone Starter-проєкт та API key, збережіть у `.env` за зразком `.env.example`. Не надсилайте ключ у чат і не завантажуйте його в Git. Переконайтеся, що в акаунті доступне створення serverless index AWS `us-east-1`; тариф і квоти перевіряйте у своєму акаунті.
2. Завантажте [arXiv Dataset](https://www.kaggle.com/datasets/Cornell-University/arxiv) і розпакуйте `arxiv-metadata-oai-snapshot.json` у корінь. Файл дуже великий; потрібне вільне місце. Скрипт читає його потоково, але проходить увесь файл, щоб репрезентативно вибрати записи.
3. Створіть Python-оточення і встановіть `pip install -r requirements.txt`. На Windows можна використати `python -m venv .venv` і `.venv\Scripts\python.exe -m pip install -r requirements.txt`. За наявності проблем сумісності зафіксованих версій скористайтеся Python 3.11 у чистому оточенні і перевірте помилку; автоматичного тесту залежностей тут не проводилося.
4. Запускайте з кореня проєкту послідовно:

```text
python scripts/01_prepare_data.py
python scripts/02_embed.py
python scripts/03_load_to_pinecone.py
python scripts/04_search.py
python scripts/05_chunking.py
python scripts/06_hybrid_search.py
```

Крок 6 — додатковий. Завантаження SPECTER2 потребує доступу до Hugging Face, достатнього місця та часу; CPU може працювати довго. Щоб змінити розмір вибірки, встановіть `MAX_RECORDS` від 5000 до 10000; шлях до джерела — через `ARXIV_JSONL`. `01` робить reservoir sampling із seed=42, а не бере перші рядки, бо ранні записи в датасеті можуть не включати сучасні `cs.LG`; точний склад залежить від версії датасету. Для повного відтворення зберігайте версію і контрольну суму джерела. Фільтр за останні 5 років залежить від року запуску і може повернути нуль результатів для певного зрізу.

Для кроку 03 створюється `arxiv-papers`, cosine, 768. Значення Pinecone cloud та region налаштовуються у `.env`. Використовуються **три namespace в одному індексі**: `papers`, `chunks-fixed`, `chunks-semantic`. Це практичний варіант при обмеженні числа індексів; формально він відрізняється від умови про два окремі індекси чанків. Якщо ментор вимагає саме окремі індекси — потрібно адаптувати код і створити їх, якщо тариф дозволяє. Наявні індекси не видаляються. Повторний запуск із тим самим набором перезаписує ті самі ID; якщо змінити датасет або параметри чанків, старі записи можуть залишитися — використовуйте новий порожній namespace або очистьте його лише після перевірки вмісту. Не використовуйте навчальні namespaces для важливих даних.

## Вибір інструментів

**Pinecone, Qdrant, Chroma.** Pinecone — керований комерційний сервіс: зручно, коли потрібні API та мінімум адміністрування. Qdrant доступний як open-source для власного розгортання, а також як керований сервіс; його зручно обрати для контролю інфраструктури та фільтрів. Chroma — open-source інструмент, зручний для локальних прототипів і невеликих застосунків, також існують серверні/хмарні варіанти. Порівнювати швидкодію загальним твердженням некоректно: вона залежить від обсягу, індексу, фільтрів, обладнання та способу розгортання; для реального вибору потрібен однаковий бенчмарк. Джерела: [Pinecone](https://docs.pinecone.io/), [Qdrant](https://github.com/qdrant/qdrant), [Chroma](https://github.com/chroma-core/chroma).

**SPECTER2.** [Картка моделі](https://huggingface.co/allenai/specter2_base) зазначає навчання на понад 6 млн трійок цитувань наукових статей і формати задач «Classification», «Regression», «Proximity (Retrieval)», «Adhoc Search». Це дає предметну спеціалізацію на наукових текстах, тоді як `all-MiniLM-L6-v2` — загальна компактна модель. Якість на нашому наборі потрібно вимірювати, а не вважати гарантовано вищою. Важливо: автори рекомендують task-specific adapters, зокрема [proximity та adhoc query](https://huggingface.co/allenai/specter2); навчальне завдання просить `specter2_base`, тому тут застосовується саме base без адаптерів. Результат не слід називати повноцінною рекомендованою конфігурацією з адаптерами.

**Метрика й pooling.** У картці base наявний приклад отримання CLS-вектора та нормалізації для retrieval, але не слід приписувати їй однозначну рекомендацію конкретної метрики без прямої цитати. У цьому проєкті обрано cosine і нормалізацію; важливо, щоб однакові preprocessing і модель застосовувалися до документів і запитів. Використано явний CLS pooling: звичайний автоматичний fallback SentenceTransformer для не-SentenceTransformer моделі може використовувати mean pooling і відрізнятися від прикладу авторів. Формат документа `title [SEP] abstract` відповідає умові. Довгі входи можуть обрізатися після 512 токенів.

**Нормалізація.** Для одиничних x і y `cos(x,y) = (x·y)/(||x||||y||) = x·y`. Через похибки float32 або однакові оцінки можливі незначні відмінності порядку.

### Семантичний пошук і фільтри

Запит `teaching machines to recognize objects in pictures` повернув першим *Flexible Compositional Learning of Structured Visual Concepts* (`cs.CV`, 2021). Серед інших знайдених є більш загальні теми AI; отже, високий score не гарантує точну відповідь. Для `reinforcement learning` з `cs.LG` і роком ≥2021 перші статті — *Human-Inspired Framework to Accelerate Reinforcement Learning* (2023) і *Adaptive Policy Learning for Offline-to-Online Reinforcement Learning* (2023). Фільтр до 2015 року повернув *Safe Exploration of State and Action Spaces in Reinforcement Learning* (2014) та інші, включно з `math.OC` — бо обмеження категорії для нього немає. Це узгоджується з умовами фільтрів. Порівняння локального точного обчислення показало однаковий порядок топ-5 для cosine, dot і L2.

### Чанкінг на практиці

За запитом `machine learning for images` обидві стратегії повернули першою *Analysing high resolution digital Mars images using machine learning*. Для `quantum field theory` у топі опинилися статті про орієнтацію Марса та операції систем, які за назвами не є очевидно релевантними. Пошук обмежений лише 30 найдовшими анотаціями, що може пояснювати слабке покриття; без аналізу всього корпусу та ручної оцінки це гіпотеза. У виводі fixed приклад починається з `the wild" emotions recognition...`, тобто фрагмента речення; відповідний чанкуванню за реченнями уривок починається з `First, already existing databases...`. За цими прикладами межі речень зрозуміліші, хоча це не доводить загальної переваги за якістю пошуку. У виводі середня довжина враховує також назву і `[SEP]`, тому не дорівнює довжині самого тексту чанка.

## Метрики

Для нормалізованих векторів cosine та dot product дають однаковий рейтинг; евклідова відстань теж дає той самий рейтинг у зворотному порядку, бо `||x-y||² = ||x||² + ||y||² - 2x·y = 2 - 2cos(x,y)`. Pinecone ANN, числова похибка та рівні оцінки можуть спричинити відмінності у видачі порівняно з точним локальним перебором. Без нормалізації dot і L2 залежать також від довжини вектора, тоді як cosine усуває вплив масштабу; рейтинги можуть відрізнятися.

## Chunking

Fixed-size ріже текст за словами й може розривати речення; overlap 30 слів частково зберігає контекст, але створює дублювання та збільшує кількість векторів. «Semantic» у цьому завданні реалізовано як **групування за межами речень**, без виявлення семантичних переходів за ембеддингами. Це зазвичай краще зберігає речення, але спрощений regex помиляється на скороченнях, а дуже довгі речення все одно розрізаються. Запуск показує реальні приклади; робити висновок про якість заздалегідь не можна. Чанк 10–15 слів часто втрачає контекст, а 500+ слів може перевищити 512 токенів і обрізатися; оптимальний розмір залежить від моделі, текстів та задачі. Перекриття збільшує покриття границь і ціну індексації/зберігання, а також може додати майже однакові результати.

## Семантичний і лексичний пошук

Семантичний пошук може допомогти, якщо запит і стаття описують ідею різними словами. BM25 часто корисний для точних скорочень, назв та імен; обидва можуть помилятися. RRF об'єднує ранги за `Σ 1/(k+rank)` незалежно від масштабів score; менше k сильніше підкреслює лідерів, більше згладжує відмінності. Документ із рангу 6–10 у двох списках може потрапити до об'єднаного топ-5, навіть якщо відсутній у кожному окремому топ-5. Жоден метод не гарантовано кращий: потрібна розмітка релевантності та метрики якості.

## Обмеження і масштабування

Актуальні квоти Starter перевіряйте в [документації Pinecone](https://docs.pinecone.io/reference/limits) та власній консолі: ліміти кількості індексів, регіонів, сховища й операцій змінюються. Умови завдання одночасно згадують один індекс і два додаткові; namespaces дозволяють ізолювати три набори в одному індексі без видалення даних, але це не три фізичні індекси. Для 10 млн статей треба оцінити вартість зберігання метаданих і векторів (768 float32 ≈ 3 KB на вектор без накладних витрат), потокову обробку і GPU-батчинг, контроль відновлення, дедуплікацію, шардоване завантаження, затримку й recall. Вибір платного тарифу потребує окремої оцінки витрат; жодних платних ресурсів автоматично не створюйте.
